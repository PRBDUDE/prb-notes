How do I setup a domain name for use in a private home lab which is not accessible outside?

Setting up a local domain name for an isolated home lab is a fantastic project. It makes accessing your self-hosted services significantly easier—allowing you to use clean URLs like [http://proxmox.home.arpa](http://proxmox.home.arpa) or [http://jellyfin.home.arpa](http://jellyfin.home.arpa) instead of memorizing a string of IP addresses and port numbers.

Here is a step-by-step guide on how to design and set up your private domain name.

Step 1: Choose Your Domain Strategy

There are two primary ways to approach choosing your domain extension (TLD):

Option A: Use a Reserved Local Domain (Completely Free)

If you want a 100% offline, local-only namespace without buying anything, you should use .home.arpa.

  • Why? It is officially designated by the IETF (RFC 8375) specifically for home networks.
  • Avoid: Older practices like using .local (which is reserved for mDNS/Bonjour and can cause routing lag and device issues) or .lan (which is not officially standardized).

Option B: Purchase a Real Domain (Recommended)

You can buy a cheap domain (e.g., yourname.com or yourname.tech for ~$10/year) from a registrar like Cloudflare.

  • Why? Even if you never point it to your public home IP address (keeping it 100% private), owning the domain allows you to easily generate valid SSL certificates (HTTPS) via Let’s Encrypt using a "DNS-01 challenge." This gives you that clean, green lock icon in your browser without exposing your lab to the internet.
  • You can dedicate a subdomain for your internal network, like *.lab.yourname.com.

Step 2: Set Up a Local DNS Server

Since your domain won't exist on the public internet, you need a local server on your network to act as the "phone book."

Popular DNS Software Options:

  1. Pi-hole or AdGuard Home: Highly recommended. They are incredibly easy to manage via a web UI, run perfectly on a Raspberry Pi or inside Docker, and double as network-wide ad blockers.
  2. Your Router (OPNsense / pfSense / OpenWrt): If you use a custom router/firewall, they have built-in DNS resolvers (like Unbound or Dnsmasq) where you can easily configure local DNS overrides.
  3. Technitium DNS / Bind9: Great if you want to learn enterprise-level DNS engineering.

Configuration Example (e.g., Pi-hole or AdGuard Home):

  • Navigate to the Local DNS Records or DNS Rewrites section of your DNS server's dashboard.
  • Add a record:
    • Domain: proxmox.home.arpa (or proxmox.lab.yourdomain.com)
    • IP Address: 192.168.1.100 (the static IP of your server)

Step 3: Tell Your Network to Use Your DNS Server

For your devices to resolve your new local domain, they must use your new local DNS server instead of public ones like Google (8.8.8.8) or Cloudflare (1.1.1.1).

  1. Log into your main home router.
  2. Locate the DHCP Server settings.
  3. Change the DNS Server IP address to point to the local IP address of your Pi-hole/DNS server.
  4. Renew your devices' network connections (or restart them) so they grab the new DNS settings.

Step 4: Handle Ports with a Reverse Proxy (Optional, but Highly Recommended)

By default, DNS only maps a name to an IP address. If your service runs on a port like 192.168.1.100:8006 (like Proxmox) or 192.168.1.100:8096 (like Jellyfin), typing proxmox.home.arpa in your browser will fail because it defaults to port 80 (HTTP) or 443 (HTTPS).

To fix this and get rid of port numbers in your URLs, set up a Reverse Proxy:

Recommended Proxies:

  • Caddy: Super lightweight and incredibly easy to configure.
  • Nginx Proxy Manager: Provides a clean, beginner-friendly web UI.

How it works:

  1. Point your local DNS records for all your services (e.g., jellyfin.home.arpa, proxmox.home.arpa) to the IP of your Reverse Proxy.
  2. Configure the Reverse Proxy to listen on ports 80 and 443.
    3. Tell the proxy: "If traffic comes in for jellyfin.home.arpa, forward it internally to 192.168.1.100:8096."

Now, typing jellyfin.home.arpa will seamlessly take you to your service without exposing anything to the outside world!
