Using module federation, provide instructions to create an angular MFE to create a menu to be shared between multiple MFEs

Creating a shared menu using Module Federation in Angular is a powerful way to ensure UI consistency without the "dependency hell" of NPM packages. By using this approach, you can update the menu in one place and have it reflect across all consuming applications instantly.

Here is the step-by-step guide to setting this up.

1. Prerequisites & Setup

Ensure you have the Angular CLI installed. You will also need the @angular-architects/module-federation plugin, which simplifies the Webpack configuration for Angular.

Bash # In your "Menu" MFE project
ng add @angular-architects/module-federation --project menu-app --port 4201

2. Create the Menu Component

In your Menu MFE, create the component that you want to share.

  1. Generate the component: ng generate component shared-menu
  2. Define the logic: Ensure your menu uses standard Angular routerLink for navigation.
  3. State Management: If the menu needs to show user data (e.g., "Welcome, Admin"), ensure that data is passed via @Input () or a shared service.

3. Expose the Component (The "Remote")

You need to tell Module Federation which component to make public. Open the webpack.config.js in your Menu MFE project.

JavaScript
const { shareAll, withModuleFederationPlugin } = require( '@angular-architects/module-federation/webpack');

module.exports = withModuleFederationPlugin({
name: 'menu_mfe', // The name consumers will use exposes: { // Key: The name to import, Value: Path to the component/module './MenuComponent': './src/app/shared-menu/shared-menu.component.ts', }, shared: { ...shareAll({ singleton: true, strictVersion: true, requiredVersion: 'auto' }), }, });

4. Consume the Menu (The "Shell" or "Host")

Now, head to the application(s) that will display the menu.

  1. Add Federation: ng add @angular-architects/module-federation --project shell-app --port 4200
  2. Configure the Host: In the webpack.config.js of your Shell app, point to the remote:
JavaScript
module.exports = withModuleFederationPlugin({
remotes: { "menu_mfe": "http://localhost:4201/remoteEntry.js", }, shared: { ...shareAll({ singleton: true, strictVersion: true, requiredVersion: 'auto' }), }, });

5. Load the Remote Component

In Angular, you can load a remote component dynamically using the loadRemoteModule helper provided by the library.

Inside your Shell's app.component.ts:

TypeScript
import { loadRemoteModule } from '@angular-architects/module-federation';
import { Component, ViewChild, ViewContainerRef, OnInit } from '@angular/core';

@Component({ ... })
export class  AppComponent implements OnInit {
@ViewChild( 'menuContainer', { read: ViewContainerRef, static: true }) container!: ViewContainerRef;
async  ngOnInit() { const Component = await loadRemoteModule({ type: 'module', remoteEntry: 'http://localhost:4201/remoteEntry.js', exposedModule: './MenuComponent' }).then(m => m.SharedMenuComponent);
this.container.createComponent(Component); } }

Inside your app.component.html:

HTML
<ng-container #menuContainer></ ng-container>
<router-outlet></router-outlet>

6. Best Practices for Shared Menus

Use a Shared Service for Navigation

If your menu needs to highlight the "active" tab based on where the user is in the Shell, ensure you are sharing the @angular/router as a singleton.

Note: In both webpack.config.js files, the singleton: true setting is vital. This ensures that the Menu MFE uses the same Router instance as the Shell, allowing routerLinkActive to work across MFE boundaries.

Handling Assets

If your menu uses local images or icons (e.g., assets/logo.png), those paths will break when loaded in the Shell because the Shell will look for them on its own server (port 4200) instead of the Menu's server (port 4201).

  • Fix: Use absolute URLs for assets in shared components during development, or configure a public path in your Webpack config.

Error Handling

Always wrap your loadRemoteModule in a try/catch block. If the Menu MFE server goes down, you don't want your entire Shell application to white-screen. You can provide a "Fallback Menu" or a simple error message instead.

Critical Success Factors

  • Routing Coordination: For the menu links to work, both the Menu MFE and the Shell app must share the same Router instance. Because we set singleton: true in the Webpack config, Angular will share the same router service across both apps.

  • Version Matching: Ensure that all MFEs use the same major version of Angular. While Module Federation allows different versions, Angular's dependency tree is strict; having two versions of @angular/core running simultaneously will likely break the application.

  • Deployment: When you deploy, the remoteEntry.js URL in your Shell configuration must be updated to the production URL of your Menu MFE.
